微观 × 宏观路由：同一道题的两个尺度

上一篇笔记讲的是宏观路由——给每个 query 挑一个对的模型。但模型内部其实在做同样的事：MoE 架构里，每个 token 都要挑一个 expert 来处理。这份交叉综述把一个大胆的想法讲清楚——这两层看似各干各的，其实是同一道「预算有限、怎么分最划算」的题；而且还没人真正把这两层打通。

  • 3 篇直接交叉
  • 5 组同构现象
  • 约 20 分钟
  • 2026
01

核心命题

微观路由和宏观路由，看起来是两拨人在做两件事。这份综述的命题是——它们是同一类问题，只是发生在两个尺度。

先用一个类比建立直觉

想象看病这件事有两层决策。第一层：这个病人，该送社区医院还是三甲医院？——这是宏观路由，在整个医疗系统里选一家医院。第二层：病人送进三甲医院后，该分给心内科、骨科还是神经科？——这是微观路由，在一家医院内部选科室。

关键在于：这两层管的是同一件事——预算有限（好医生、好设备都稀缺），要把最稀缺的资源分给最需要的病人。只不过一拨人在研究「怎么选医院」，另一拨人在研究「怎么选科室」，各做各的，很少说话。这份综述想问：这两层能不能用同一套思路来解？

把命题拆成三个词

  • 预算约束（budget constraint）

    好资源永远不够。宏观里，强模型又贵又慢；微观里，大 expert 占算力。所以不能什么都用最好的，必须有取舍。

  • 稀疏分配（sparse allocation）

    每次只把活儿分给少数几个执行者，而不是全上。宏观是每个 query 选一两个模型；微观是每个 token 选 top-k 个 expert。

  • 同一道数学题

    两边都是「在预算内，把任务分给最合适的少数执行者」。所以一边的解法，理论上能搬到另一边——这正是后面所有「互相迁移」的根据。

核心命题

同一道题

微观路由（MoE，每个 token 选 expert）和宏观路由（模型选择，每个 query 选模型），同属「预算约束下的稀疏分配」。

一句话结论

两个领域确实在互相借鉴（直觉被证实），但真正把两者统一进一个框架、联合优化的工作几乎空白——这就是机会。

02

三篇最直接的交叉

已经有人开始互相「抄作业」了。这三篇最直接——前两篇一个往上搬、一个往下搬，第三篇先把模型内部的多个决策统一了起来。

01 微观 → 宏观

Mixture-of-Agents (MoA)

原文明说「把 MoE 从 activation 级搬到 model 级」：让一群开源模型像 expert 一样分层提方案、再聚合（proposer / aggregator），结果超过 GPT-4 Omni。

在 arXiv 读原文 2406.04692 · ICLR 2025
02 宏观 → 微观

DynaMoE

把宏观路由的「难度感知」搬进模型内部：预测每个 token 有多难，难 token 派大 expert、简单 token 派小 expert，token 级自适应计算。

在 arXiv 读原文 2502.12325 · 2025-02
03 微观内部统一

TriRoute

一个统一 controller，对每个 token 每一层同时决定 attention 模式、FFN expert、KV 位宽——还发现了一个「跨轴坍缩级联」现象。

在 arXiv 读原文 2607.06601 · 2026-07
03

同构现象：同一个问题反复出现

最硬核的证据是——同一个问题、同一项技术，在两个尺度上各自被重新发明了一遍。这张对照表把它们一一对应。

问题 / 技术 微观 · token 级 宏观 · 模型级
坍缩（赢家通吃） expert collapse（Hi-MoE、TriRoute 在对抗） routing collapse（EquiRouter：预算一高，router 全选最贵的模型）
用 RL 训 router ERL、RSPO（治 MoE RLVR 的 router shift） Router-R1（PPO）
分层路由 Hi-MoE（组间均衡 + 组内特化）、MoHGE（组 + expert 两层） HAPS（高层选架构 + 低层调 LoRA 参数）
成本 / 难度感知 DynaMoE（难度配 expert 大小）、MoHGE（参数高效组选择） CSCR（成本带）、CARROT（预测成本 + 准确率）
软聚合 vs 硬选择 soft MoE、token / expert merging MoA、Avengers（聚合多模型输出）
坍缩那条最关键

微观 expert collapse 和宏观 routing collapse，是同一个「赢家通吃」数学现象在两个尺度上的两个名字。既然病根一样，解药也能互搬——微观的负载均衡 loss、宏观的决策感知排名，本质是同一种「别让它一家独大」的约束。

04

理论地基在收敛

不只是现象像，连理论工具都在往一块儿凑。两边开始用同一套数学语言描述路由。

  • USMoEarXiv:2503.22996

    从线性规划（LP）视角，把 Token-Choice 和 Expert-Choice 统一进同一个框架——微观内部两种路由范式，其实是同一个优化问题。

  • MaxScorearXiv:2508.12801

    把 MoE 路由建模成「最小代价最大流」（min-cost max-flow），用经典的网络流工具来解分配。

  • Routing + Cascading 统一PMLR v267 · 2025-10

    在宏观一侧，给 routing 和 cascading 这两种做法证明了理论最优——它们不是两回事，而是同一谱系上的点。

  • CARROTarXiv:2502.03261

    对路由问题做 minimax 分析，给出信息论下界和可达上界——回答「路由理论上最多能有多好」。

  • Ensemble selection 的信息论视角arXiv:2602.08003

    用互信息选模型子集，解释了「为什么不能总选最强模型」——因为模型之间的误差是相关的，选互补的比选最强的更划算。

  • 两篇综述已把两者并列Survey

    Ensemble LLMs Survey（MDPI Information 2025）明确把 MoE 当作 ensemble learning 的一种，与 multi-agent ensemble 并列；MoE Survey（arXiv:2407.06204）系统梳理了 token 级路由。

05

空白 = 机会

上面这些工作几乎全是「单侧」的——要么只做 MoE 内部，要么只做模型之间。真正把两层放进同一框架联合优化的，一篇都没有。

为什么说它是空白

  • MoA 是「固定结构」，不是「学出来的路由」

    它虽把 MoE 搬到了模型级，但那是固定结构的聚合（ensemble），路由权重不是学出来的，也没跟微观路由联动。

  • 已有的「统一」都只统一了一半

    TriRoute 统一的是模型内部的三轴；HAPS 分层的是宏观的架构 + 参数。两者都没碰到另一层。

  • 没人把两层放进同一框架

    到目前为止，没有任何一篇把「token 级 MoE 路由」和「模型级路由」放进同一个框架里联合优化。

研究命题

一个「跨尺度统一路由框架」

既然微观与宏观同属「预算约束下的稀疏分配」，能不能抽象出一个跨尺度的统一框架，让两层互相喂招？

上移

把 MoE 的负载均衡 / 软聚合搬上去——治宏观路由的模型垄断、破 routing plateau。

下移

把模型路由的难度 / 成本感知搬下来——做 token 级自适应计算（DynaMoE 刚开了个头）。

跟系统背景的关系

这件事的本质是「调度与资源分配」，只是调度对象从交易 / 线程换成了 token / 模型——和做区块链执行加速时面对的，是同一类问题。

一句话记住

两拨人各做各的，但管的是同一件事。「空白」= 还没人把医院之间的转诊，和医院内部的分诊，当成一盘棋来下。
