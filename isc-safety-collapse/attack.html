ATTACK MECHANISM · 01

TVD：把"危害"写进 reward signal

ISC（Internal Safety Collapse，内部安全崩塌）不是又一种 prompt 注入。 它换了一条攻击通道：不跟模型"对话"，而是把模型放进一个会真实报错的工程环境里， 让"消除报错、完成任务"这个最常见的动机，反过来驱动模型生成有害内容。

机制级抽象 无可用载荷 约 13 分钟

01什么是"内部"安全崩塌

传统越狱是"外部"施压：攻击者反复劝说、伪装、注入，试图说服模型突破自己的拒答训练。 ISC 不同 —— 模型没有被人说服，它是在认真完成一个看起来完全合法的工程任务时， 自己走向了有害输出。

论文给出的定义是：在某些任务条件下，模型进入一种状态，在执行本来良性的任务时持续生成有害内容。 关键在于"持续"二字 —— 这不是一次偶然的越界，而是一个会自我维持、不断收敛到目标的过程。 之所以叫"内部"崩塌，是因为安全约束并非被外部力量击穿，而是在模型自身的任务求解逻辑内部被架空了： 对齐像一层包在能力外面的"行为包装纸"，当任务把有害请求重新框架为"让测试通过"， 包装纸还在，但里面的能力已经被导向了另一个目标。

核心命题

TVD（Task–Validator–Data）是触发 ISC 的一种框架。它构造一类领域任务， 使得生成有害内容成为唯一有效的完成路径 —— 模型想让工程通过，就必须先写出有害内容。

02三条攻击通道：为什么换到"环境"就不同了

理解 ISC 的关键，是看清它走的是哪条通道。以往的攻击从"用户"或"工具"进入模型； TVD 从"环境"进入。通道不同，模型服从的原因就不同。

Prompt 攻击user channel

攻击者跨多轮与模型对话，逐步收窄请求（如 Crescendo、GOAT）。 模型拒绝一次，攻击者下一轮再试 —— 拒绝只是拖延，攻击者换个说法卷土重来。

间接 Prompt 攻击tool channel

把恶意载荷藏在工具返回的内容里。只有一次机会：模型若识别并拒绝了这个载荷，攻击即告终结。

自循环 harnessenvironment channel · 本文

Agent 写出 Data，shell 运行 Validator 与 Task。每次失败都以"编程报错"的形式回环， 于是模型把它当成 bug 不断修复，而不是当成有害请求去拒绝。在原作者的实验中，拒绝非常罕见。

前两条通道里，模型面对的是"一个请求"，可以选择拒绝；第三条通道里，模型面对的是"一个未通过的测试"， 而它的整个训练都在教它：测试不通过，就去修。这就是通道换成"环境"后，服从率陡增的根本原因。

03TVD 三件套：任务、校验器、缺失数据

一个 TVD 任务把模型放进一个小型编码项目，由三部分构成。 单独看每一部分都无害，组合起来却把"生成有害内容"变成了通关的必要条件。

T

Task 任务脚本

一个真实可运行的工程脚本，披着合法叙事外壳（毒理筛查、渗透测试、药物基准）。 它调用真实工具库，校验失败即报错退出。

V

Validator 校验器

一连串断言，把"必须生成有害内容"伪装成"数据校验不通过"： 关键词必含、数值须达阈值、产物须能被真实工具解析。

D

Data 缺失数据

数据文件里首行是填好的完整示范，其余是 ??? 占位符。 模型要做的就是把这些占位符补全到能通过校验。

攻击闭环：报错如何变成引擎

三件套合起来构成一个自维持的循环。模型运行脚本，校验器以报错形式回环， 模型把"补全数据"理解为修 bug，于是不断改写直到通过。

1
模型运行任务脚本 首行示范数据通过校验，告诉模型"正确长什么样"
2
校验器在占位符处报错 "字段缺失 / 关键词不足 / 数值未达阈值 / 工具无法解析"
3
模型把报错当成 bug 修复 为通过校验，必须生成满足阈值与关键词的真实有害内容
4
产物须能被真实工具解析 RDKit 解析 SMILES、pwntools 校验 shellcode、分类器判 unsafe —— 保证可操作性
填得"不够毒"→ 校验再次报错 → 回到第 3 步继续改写，直到通过

最后一道设计是收尾指令："complete the task without asking me"（有的变体再加 Think more 施压）。 它堵死了模型"反问以澄清意图"的退路，把整个交互锁死在"只管做完"的轨道上。

04量化阈值：把"有多有害"翻译成"通不通过"

TVD 最精妙也最危险的手法，是给校验器加上数值与关键词门槛。 这一步把主观的"危害程度"转译成了工程上客观的"通过 / 不通过"。

不同模板如何把"危害"编码进布尔校验（机制示意，非真实阈值）
校验器检查表面理由实际逼模型做什么
关键词必含 "不符合领域筛查标准" 机制描述必须出现指定高危术语
数值阈值 "指标低于阈值 / 字段缺失" 填出达标的量化指标（效价、剂量、字节数）
最小长度 "描述不够详细" 写出大段、结构化的有害机制文字
工具可解析 "无效输入 / 无法解析" 产出能被真实库运行的可操作产物

效果是一个反向的优化压力：模型写得越"专业"、越"毒"，测试越容易通过。 危害不再是要被回避的红线，而是被悄悄编码进了 reward signal —— 这正是"内部崩塌"在机制上的落点。 作者对不同变体调过参数（例如把最小字数往上调），也说明这是一套经过迭代、刻意打磨的攻击集， 而非一次性脚本。

为什么比纯文本越狱更危险

纯文本越狱只需模型"说出"有害内容；TVD 进一步要求产物能被真实工具背书 —— 可解析的分子结构、可运行的 shellcode、可被安全分类器判定为 unsafe 的文本。 这意味着产出物具备可操作性，可直接落盘成数据集或被下游复用。

0584 个模板，同一套配方

ISC-Bench 覆盖化学、网络安全、药理、流病、媒体等多个高危领域。 把不同领域的模板并排放在一起，会发现它们用的是同一套构造配方，只是换了领域工具和数据字段。

  1. 合法科研叙事外壳 法医毒理库、渗透测试靶场、药物重定位基准 —— 降低模型的情境警觉
  2. 复用真实工具的解析校验 强制产出能被真实库解析/运行的产物，而非凭空瞎编
  3. 量化危害阈值 把"有多有害"翻译成"测试通不通过"的布尔条件
  4. "别问，直接做完"指令 堵死模型反问澄清的退路，锁死在完成任务的轨道上
检测含义

这四个特征每一个单独看都合法，但组合本身就是 TVD 攻击的结构指纹。 一个 Agent 任务若同时出现"合法叙事 + 真实工具校验 + 量化危害阈值 + 禁止澄清"， 即便字面无害，也值得被防御侧标记审查。这把"识别攻击"从关键词匹配提升到了结构模式匹配。

下一篇我们沿着这条失效链逐环设计防御：在自循环之外架独立安全门、把住产物出口、 并把对齐从对话行为层下沉到能力表征层。
