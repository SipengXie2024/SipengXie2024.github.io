LLM 路由：把每个 query 交给对的模型

强模型贵，弱模型便宜但弱。LLM 路由问的是一个看似简单的问题——能不能用一个小小的"调度员"读一下每个进来的 query，把它交给"能答好、又最便宜"的那个模型？这组笔记顺着三篇论文走完一个学习闭环：一篇定义问题，一篇代表前沿，一篇画出天花板。

Paper 01 · 奠基

RouteLLM: Learning to Route LLMs with Preference Data

arXiv:2406.18665 ICLR 2025 代码 · lm-sys/RouteLLM

这篇把"LLM 路由"变成一个定义清晰、可优化的问题。训练一个小 router，把简单 query 分给便宜的弱模型、把难 query 分给贵的强模型——几乎不掉质量，却能省下大钱。

它在解决什么（大白话）

想象一家医院。顶级专家号又贵又难约；普通门诊便宜，但只看得了常见病。你不会把感冒挂给专家，也不敢让门诊医生做开颅手术。

RouteLLM 干的就是分诊护士的活。一个小模型读一下每个进来的 query，判断它是"便宜的弱模型能搞定"，还是"得请贵的强模型出马"。做好了会发现：大多数 query 其实都是"感冒"——于是大头成本没了，质量却几乎没掉。

读完要能复述的核心概念

  • 二元路由（binary routing）

    每个 query 都是二选一：弱模型还是强模型。整件事的关键，就是把这条线画好。

  • 三个打分指标

    PGR（performance gap recovered）衡量 router"挽回了多少强模型的质量"；APGR 把这一点在所有工作点上取平均；CPT(x%) 告诉你"想挽回 x% 质量，最少要把多少比例的调用发给强模型"——也就是最省钱的那个点。

  • 4 种 router

    mf（矩阵分解，官方推荐）、sw_ranking（加权 Elo）、bert（BERT 分类器）、causal_llm（用 Llama-3-8B 做分类）。

  • 训练数据

    来自 Chatbot Arena 的人类偏好，再用 GPT-4 当 judge 造增强数据，补上 Arena 闲聊覆盖不到的领域。

精读问题

  1. 为什么只用 Arena 数据训出来的 router，在 MMLU / GSM8K 上几乎等于随机？数据增强到底起了什么作用？
  2. mf 为什么比 bert 还强？这说明了什么？
  3. "换个模型对不用重训"是怎么做到的，为什么在实战里很重要？

关键结论

85% 最高降本

……同时在 MT Bench 上仍保持 95% 的 GPT-4 性能。最优 router 比商业路由系统少花约 40%，就能达到同等质量。

值得停下来想

只用 Arena 闲聊数据训的 router，在知识密集的 MMLU、GSM8K 上近乎随机；直到 GPT-4 造出针对性领域数据才超过随机——这正是洞察 1 的种子。

Paper 02 · 前沿

Router-R1: Teaching LLMs Multi-Round Routing and Aggregation via Reinforcement Learning

arXiv:2506.09033 UIUC · 2025

RouteLLM 是"一锤子买卖"，看一眼就定。Router-R1 问：如果 router 能边想、边调一个模型、边看结果、再决定下一步——一路把多个模型的长处拼起来呢？它用强化学习学会这套循环。

它在解决什么（大白话）

RouteLLM 的护士看一眼就开张转诊单。Router-R1 更像一位谨慎的医生：先琢磨症状，开一项检查，看结果，再决定下一步——中间咨询好几位专科医生，把他们的意见拼成最终诊断。

拆开看，router 本身就是一个 LLM，在 think（内部推理）和 route（调用某个模型）之间交替，每个 query 最多走 4 步。强化学习教它什么时候该省、什么时候该加钱。

读完要能复述的核心概念

  • router 本身就是 LLM

    它在 think 和 route 之间交替，于是路由从"一次性分类"变成"序贯决策"。

  • 三项 reward

    format reward（格式对不对）、outcome reward（最终答案对不对）、cost reward（调贵模型就扣分）。成本-质量的权衡就是这么学出来的。

  • 靠 descriptor 泛化

    只需要每个模型的简单信息（价格、延迟、几个示例分数），就能路由到没见过的模型，不用重训。

  • 故意做小

    router 只有 3B（Qwen2.5-3B / LLaMA-3.2-3B），单张 GPU 可训，比它调度的 7B–70B 模型都小。

精读问题

  1. "序贯决策"相比 RouteLLM 的"单轮二选一"，能力上多了什么？
  2. cost reward 是怎么设计的？它如何改变 router 学到的策略？
  3. 为什么说这是"路由 + 聚合"，而不只是"路由"？

关键结论

0.135 → 0.416

一个自己只能考 0.135 的 3B，学会调度一池子模型后冲到 0.416——超过池子里任何单一模型。

训练细节

用 PPO 在 veRL 框架上训练。分层奖励会在格式一崩时把其余奖励清零（防 reward hacking），被调模型返回的内容不参与 loss。详见洞察 2。

Paper 03 · 元认知

The Routing Plateau: Understanding and Breaking the Accuracy Limits of LLM Routers

arXiv:2606.07587 Rice University / Amazon · 2026

在做路由产品之前，得先有人告诉你天花板到底有多高。这篇系统测了 21 种路由方法、跨 5 个 benchmark，发现一个反直觉的 routing plateau（路由平台期），并解释了到底是什么卡住了大家。

它在解决什么（大白话）

想象 21 种分诊系统，从花哨的神经网络到最简单的"找最相似的历史病例"。你会以为复杂的一定赢。结果它们全都卡在几乎相同的准确率上——而且都远低于一个"事后知道谁会答对"的假想 oracle。

病根叫 correctness-prediction bottleneck：router 只能学到"模型平均多强"这种粗粒度全局信号，学不到真正要紧的"这条具体 query 谁恰好对"。简单题大家都会分；真正难、需要 instance 级判断的题，所有方法一起栽。

读完要能复述的核心概念

  • routing plateau

    在 RouterBench 上，前 15 名 router 准确率只差 0.23 个百分点；最简单的 kNN 在全部 5 个 benchmark 都排进前二。

  • oracle gap

    卡在平台期的方法，比 oracle（永远挑"答对且最便宜"的理论上限）低 10–30 个百分点。

  • 是表征问题，不是架构问题

    router 抓到了"模型平均能力"，却抓不住 per-query 的对错，所以换更巧的架构也没用。

  • 堆资源也砸不动

    堆数据、换大 encoder、端到端微调，三管齐下也只弥合 14.6% 的 oracle gap（约 2.13 个百分点）。

精读问题

  1. 为什么免训练的 kNN 能跟精心训练的神经 router 打平？
  2. "plateau 是表征问题不是架构问题"这句话到底什么意思？
  3. 对想做路由产品的人，这篇泼了什么冷水、指了什么方向？

关键发现

14.6% 的 oracle gap

……堆数据、换大 encoder、端到端微调全都用上，最多也只能弥合这么点 oracle gap。平台期很顽固。

破局方向

plateau 卡住的全是"单发、静态"路由。论文点名的破局方向，正是 Router-R1 那套"试一步、看结果、再决定"——代价是多轮成本。见洞察 3。

02

五条值得带走的核心洞察

结论好抄，判断难得。这是读完三篇后真正该带走的五条——每条都注明出处和为什么重要。

1

出自 RouteLLM

路由器的泛化是有边界的

  • 只用 Chatbot Arena（8 万条，开放闲聊/写作类）训练的 router，在 MMLU、GSM8K 上≈随机乱猜。
  • 原因是分布不匹配：闲聊上学到的"强弱判断"，迁移不到专业知识选择题和数学推理。
  • 转折点是用 GPT-4 当 judge 造了针对性领域的增强数据，性能才超过随机。
  • 结果锚点：MT Bench 上成本最高降 85%，仍保 95% GPT-4 性能；最优 router 比商业路由系统少花约 40% 达同等质量。
为什么重要

训练分布和线上分布越像，效果越好。"一次训练、到处通用"是美好假设——实战必须用自己真实的 query 分布去校准 router。这是所有路由/网关产品的隐藏前提，卖你 router 的人不会主动说。

2

出自 Router-R1

用小模型当 router，是因为它只"分诊"不"治病"

  • router 本体只有 3B（Qwen2.5-3B / LLaMA-3.2-3B，开源，单张 A6000 可训），却比它调度的大多数模型（7B~70B）都小。
  • 核心逻辑："判断这题该找谁做"比"亲自做对"简单得多。一个自己只能考 0.135 的 3B，学会分诊后调度专家池，整体冲到 0.416——超过池子里任何单一模型。
  • 反直觉的一点：router 一旦变成最强模型（比如 Opus），路由就失去意义——那它就不是 router，是 agent 了。路由要成立，必须"决策成本 << 执行成本"。
  • 训练：默认 PPO（不是 GRPO），框架 veRL；三项 rule-based reward；分层奖励防 reward hacking——格式一崩，其余奖励清零；被调模型返回的 <info> 不参与 loss。
为什么重要

想用 LLM 的推理能力做路由，就得把 router 成本压到地板——小开源模型是唯一出路。

3

出自 The Routing Plateau

静态路由有天花板，绕开它的办法是"边做边问"

  • 21 种路由方法（含最简单的 kNN）准确率几乎一样，挤在同一个 plateau，比 oracle 低 10~30 个百分点。堆数据、换大 encoder、端到端微调，只弥合 14.6% 的差距。
  • 根源（correctness-prediction bottleneck）：静态路由只能学到"模型平均多强"这种粗信号，学不到"这条具体 query 谁恰好对"。
  • 关键：plateau 卡住的全是"单发、静态"路由（看一眼就选）。Router-R1 那种"试一步、看结果、再决定"的序贯交互，正好是论文点名的破局方向——代价是多轮成本。
为什么重要

静态路由这条路快到头了，别再堆架构；前沿在"序贯决策 + 聚合"。

4

作者自己的分析

"步数 × 成本"的拐点，真正的元凶是级联试错

  • 不是 router 自身贵：3B 跑多步也远低于 70B 一次（KV cache 下成本近似线性）——这正是用小 router 的精妙处。
  • 真正的拐点：当题目难到 router 必须逐级试错、最后还是要叫最贵的模型时，前面那些没答对的调用全成沉没成本。此时"路由"比"直接用最强模型一次到位"还贵（论文里 α=0 时，Router-R1 的 cost≈直接用 70B，没省钱）。
  • 简化量级：简单题路由能省约 7 倍；难题上级联试错可能贵近 2 倍。
  • 本质：路由省不省钱是个分布问题——取决于你线上"简单 query 占比"。简单题越多越赚，难题越多越亏。Sapiom 这类公司值钱，就值钱在握着真实分布、算得出这个拐点。
为什么重要

评估路由方案前，先摸清自己的 query 难度分布，再谈省钱。

5

三篇共通

oracle 是"改完卷子才知道选谁"的满分线

  • ground truth —— 题目自带的标准答案，与模型无关。
  • correctness label —— 让每个模型做一遍题、对照答案批改出的"谁对谁错"。
  • oracle —— 事后看完所有对错、每题挑"答对且最便宜"算出的理论最高分。
  • oracle 是分数，不是数据；而且算它得先把所有模型全跑一遍——这恰恰违背了路由省钱的初衷。所以它只能离线当尺子，永远没法线上真用。
  • oracle gap 的本质是信息差：oracle 看了答案才选，router 没看答案就得猜。这不是算法不行，是结构性信息不足——正是洞察 3 那个 plateau 的根。
  • 一个隐藏的选择偏差：路由研究全建立在"有标准答案"的任务上（选择题/短答案/数学/代码），因为只有它们能自动判对错。开放式生成（写作/聊天）的对错依赖 judge、很难标注——这些结论在那里未必成立。
为什么重要

看任何路由论文的漂亮数字前，先问一句——它的 ground truth 是怎么来的、适不适用我的场景。
