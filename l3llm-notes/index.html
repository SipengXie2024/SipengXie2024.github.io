论文一句话

现代服务器 CPU 靠 3D 堆叠缓存有了 GB 级 L3(AMD EPYC 9684X 单 socket 1152MB)。 这篇论文把 LLM decoding 的权重和 KV cache 整个驻留进 L3,绕开 DRAM 带宽墙, 实测比同等硬件条件的 llama.cpp 快 2.04–11.51 倍 TPOT。

01

第一个疑问:CPU 凭什么跑机器学习?

第一反应和所有系统背景的人一样:CPU 的并行能力跟 GPU 差远了,这不是以卵击石?

先统一背景。LLM 生成文字是一个 token 一个 token"蹦"出来的(自回归),模型每次前向计算只做一件事: 给定前面所有 token,算出下一个。这个逐 token 的循环就叫 decoding: 

输入: "今天天气"
第 1 步: 模型(今天天气)     → 预测出 "很"
第 2 步: 模型(今天天气很)   → 预测出 "好"
第 3 步: 模型(今天天气很好) → 预测出 "，"
…… 直到模型输出结束符

每蹦一个 token,就要把整个模型的所有权重完整过一遍——3B 模型就是每 token 读 3GB(INT8);生成 1000 个 token,就是过 1000 遍全模型。

关键在于 decoding 不是算力游戏,是带宽游戏。Decoding 每生成一个 token 要把全部权重过一遍, 核心计算是矩阵乘向量(GEMV),每个权重元素只用一次,算术强度只有 2–5 FLOPs/Byte。 一块 H100 要打满算力需要约 600 FLOPs/Byte——也就是说 GPU 跑小 batch decoding 时, tensor core 利用率可能不到 1%,瓶颈完全卡在"每秒能从显存流出多少字节"。

Fig. A · 算术强度错配:GPU 算力在 decoding 上为何闲置(FLOPs/Byte)

数量级估算。差距约两个数量级:瓶颈在数据流出速度,不在乘加算力——这就是"CPU + 大 L3"有资格上桌的原因。

所以真正的竞赛是权重从哪流出来:GPU 从片外 HBM 流,L3LLM 从片上 L3 流。 HBM 再快也是片外,L3 是片上。论文赌的是片上缓存带宽能追平片外显存带宽,而硬件便宜得多、还容易买到。

至于 CPU 的短板,论文是承认之后用软件补:跨核全局 barrier 太贵,就做细粒度同步; OpenMP 调度开销在微秒级 kernel 面前嫌贵,就自研静态绑核线程池;算力不够, 就 INT8 + AVX-512 VNNI,并且只认领内存受限的 decoding,算力受限的 prefill 明确不碰。

02

地基:KV cache 到底是什么

后面所有推导都建立在这上面。Transformer 每一层的 attention 在算第 N 个 token 时都要回看前 N-1 个, 而历史 token 在每层算出的 K、V 向量一旦算出就永远不变,所以推理引擎把它们存下来重用——这就是 KV cache。

看一遍它边跑边攒的过程(模型只有 2 层,输入"今天天气"):

处理"今":  层1 算出 K(今)V(今) → 存;层2 也算出自己那套 K(今)V(今) → 存
处理"天":  层1 直接取出存好的 K(今)V(今) 来用,再把 K(天)V(天) 追加进去;层2 同理
……
到第 100 个 token: 层1 存着 100 对 K/V,层2 也存着 100 对

它的物理结构决定体积是三个维度的乘积:

  • 层数:每层的 K/V 是独立的一套,8 层存 8 份;
  • 对话数:每条对话的历史不同,KV 完全私有,10 条并发对话就是 10 份(对比:权重是所有对话共用一份);
  • 上下文长度:聊得越长,攒的越多。

Fig. B · KV cache 的结构:层 × 时间 × 对话

已积累的历史 K/V 本 token 新追加

每生成一个 token,每条对话的每一层都向右追加一格。层数翻倍 → 份数翻倍;对话翻倍 → 整摞翻倍;上下文变长 → 向右无限延伸。

03

KV 悖论:这篇论文的"题眼"

目标是把权重和 KV 都放进 L3。模型大了怎么办?按层切到多台机器(流水线并行)。 论文证了一个反直觉的结论:加机器能摊薄权重,但摊不薄 KV。

纯数字推导(8 层模型,一条对话每层的 KV 算 1MB,一条对话完整 KV 就是 8MB,钉死不变):

  • 2 台机器:每台 4 层;流水线要不空转就得 2 条对话同时在跑;每台要存 4 层 × 2 条 = 8MB;
  • 4 台机器:每台 2 层;要 4 条对话填满;每台 2 × 4 = 8MB;
  • 8 台机器:每台 1 层;8 条对话;每台 1 × 8 = 8MB。

流水线有 p 段,就得有 p 条对话同时在流动——在途对话数被迫等于机器数,这就是悖论里那个"× p"的来源。

4 台机器同理:1 条对话时每台 3/4 时间空转,要塞 4 条才填满。规律就是流水线有几段, 就得有几条对话在流动——这个对话数是被迫的,不是你选的。

机器每翻一倍,"每台分到的层数减半"和"每台要管的对话数翻倍"是同一个动作的两个后果,恰好抵消。

再直观看一眼"每台 8MB"的组成。4 台机器时,机器 1 上实际存着:

对话A 的第1-2层 KV + 对话B 的第1-2层 KV + 对话C + 对话D = 8MB

8 台机器时变成:

对话A~H 的第1层 KV,各一份 = 8MB

随机器数变化的只是 8MB 的组成方式(层越来越少 × 对话越来越多),总量不变。

示意数值:8 层模型、每层 1GB 权重;每条对话每层 1MB KV。左面板一路下降,右面板被"层数 ÷ p × 对话 × p"锁死在 8MB。

不管怎么切,每台机器背上永远恰好是一整条对话的完整 KV。

这在 DRAM 时代无所谓(内存大),但 L3 是固定预算(1.15GB/socket):KV 随上下文膨胀, 把权重挤出 L3,缓存驻留就破功——而且加多少机器都救不了。这就是悖论。

04

出路:权重和 KV 为什么可以分开

拆开一层看数据流,每一步计算要摸的东西要么是权重、要么是 KV,从不同时摸:

  • QKV 投影、输出投影、FFN:只用权重,不关心历史;
  • attention(softmax(QK^T)V 那一步):只用 KV 历史,一个权重参数都没有。

"当前"和"历史"在一层里只相遇一次,且相遇时权重已经退场。所以把权重放"权重机"、KV 放"注意力机", 语义完全不变,交界面上每 token 只传几 KB 的小向量——大块头都不动。这就是 WA 分离。

但追问下去会发现:KV 有两个独立的维度(层、对话),摆到机器上有两种切法。把 KV 想成一张方格表 (2 条对话、4 层),每个格子是"某层 × 某对话"的一份 KV:

加第 3 台机器时分晓立现:摆法一里新机器是流水线的新一段——层重新摊、被迫更多对话在途, 每台总量不变(正是悖论);摆法二里新机器只是池子里多一个位置,新对话放上去就行, 每台 KV 真的降下来了。论文的实测和主张之间有条缝:

摆法一:按层切 KV摆法二:按对话切 KV
怎么摆 每台注意力 socket 存"本机几层 × 所有在途对话" 每条对话完整归属一台注意力机
效果 KV 总量没变,但权重和 KV 各独占一个 socket 的 1.15GB,互不挤占 加机器不再加深流水线,悖论真正解开
论文证据 实验全是这种;7B 上实测收益 1.13 倍,中等 只是 §3.1 的架构主张,没有实验真的挂第二台注意力机

再追一刀,摆法二有硬下限:单条对话的 KV 是原子的。7B 模型 INT8 下一条 4K 上下文的对话, 全模型 KV 约 1GB——一台 socket 的 L3 几乎只够一条;32K 上下文约 8GB,单机想都别想。 所以"所有 KV 永远驻留 L3"在长上下文下数学上不可能。论文真实的承诺(§3.1)是: 权重永远驻留;KV 尽量驻留,装不下就在注意力机局部溢出到 DRAM,不连累权重。

05

亚算子同步:同一个思想的第二次应用

缓存驻留后 kernel 从毫秒缩到微秒,原本无所谓的"算子边界全局 barrier"浮出水面: 96 个核对一个共享计数器原子加,缓存行在 96 核间来回过户;而且 attention head 之间明明互不依赖,却要互相等。

改法:每个 head 算完自己发"就绪"信号,不等别人;FFN 这种躲不开的汇合,用树形层次化同步 (CCD 内先汇合,再每 CCD 出一个代表),把扇入从 96 锁到小组规模。

这和 WA 分离是同一个原则在两个维度的应用:WA 解的是"空间上不该住一起的数据", 亚算子解的是"时间上不该锁步的计算"——同步/共置的粒度应该对齐真实依赖,而不是对齐抽象边界。 这个原则大概是这篇论文之外最能带走的东西。

06

数字该怎么读

论文的性能模型就三句话:总延迟 = 段数 × 单段耗时;吞吐 = 单段耗时的倒数;单段耗时 = 数据量 ÷ 带宽。 前两句是流水线常识,第三句指出两个旋钮:切机器拧小数据量(KV 拧不动,见悖论),驻留 L3 拧大带宽。

Fig. F · 实测 TPOT 对比:LLaMA-3.2-3B,ctx 4096(越低越好)

llama.cpp L3LLM

数据:论文 Table 2(a),端到端实测。batch 越大,llama.cpp 越能摊薄从内存读权重的成本,加速比从 11.5× 收窄到 2.8×——这是 ground truth,不是外推。

评估方法上,大模型的数字(Qwen-8B、70B,最高 13.9×)不是实测:他们在真机上掐表单段耗时, 套公式组合出端到端,再用 3B/7B 实测校准。校准显示估计值系统性偏小 15%–52%(漏算跨节点干扰和缓存抖动), 所以外推图要按"趋势可信、绝对值偏乐观两三成"来读。

Critical Takeaways

批判性结论

大头在哪2–11.5 倍的大数字主要来自"缓存驻留"本身;WA 分离和亚算子同步的消融各值 1.0–1.5 倍——作者消融做得坦白,加分。
Prefill 空白全文只有两句话,(see §6) 是悬空引用。Agent 时代(prefill 重、并发高、输入远多于输出),"decoding 主导"的前提正在过时。
甜区小 batch、长生成、低并发、延迟敏感的交互负载 + GPU 买不到的部署环境。Batch 32 时加速比掉到约 2 倍。
没有免费切法KV 三刀各有墙:按层切有悖论,按对话切有单条对话的下限,按时间切有每 token 的归并税。
07

方法论:这次阅读本身的收获

  • 盯住 motivating premise 问"今天还成立吗"——论文的"decoding 占主导"是基于昨天的负载写的;
  • 分清"实测到的"和"声称可扩展的"——摆法一 vs 摆法二就是这条缝;
  • 自己拿公开参数算一遍数——每层 KV 8KB、每 socket 分 0.86GB,一算就发现配置表全是精心卡在 1.15GB 以内的;
  • 没懂就追问到底——KV 悖论我追了四五轮才真懂,每次"没懂"都指向一个更基础的概念缺口。
